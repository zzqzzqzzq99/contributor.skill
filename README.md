# contributor.skill

**让每个人都可以成为贡献者。**

把你与 AI 长期协作形成的经验，转成值得被采纳的开源贡献。

你可能已经用 AI 做过很多事：处理文件、写程序、分析数据、研究问题，或者把反复踩坑的过程整理成了一套 SOP。Contributor 让个人 Agent 先理解这些积累，再检索当前 GitHub 项目，找出你能提供帮助的地方，完成一个有证据、可验证、容易审阅的贡献。

这是一个供 Agent 读取的 **Skill**，不是自动刷 PR 的服务。它不内置模型、账号或历史记录访问权限，也不承诺贡献会被合并。

## 从私人经验到公共贡献

```text
归纳个人使用 AI 的领域
          ↓
检索当前相关开源项目
          ↓
个人实践与 SOP × 技术进步 × AI 分析能力
          ↓
验证一个具体机会 → 完成必要改动 → 提交 PR
          ↑                              ↓
          └──────── 维护者反馈 ──────────┘
```

- **个人获得可核验的经历**：把经验变成真实补丁、测试或方法，积累协作记录，可据实用于简历与作品集。
- **维护者获得有用的贡献**：来自真实使用场景的判断和经过验证的改进，范围清楚，减少审阅负担。
- **社区获得可复用的智慧**：原本留在个人对话里的经验，经提炼后成为公共成果。

提交是行动，采纳是认可。Skill 会明确区分提交、合并和关闭状态；不会把 PR 数量或“使用过 AI”包装成专业能力证明。

## 开始使用

入口是 [skills/contributor/SKILL.md](skills/contributor/SKILL.md)。机器标识为 `contributor`；`contributor.skill` 是项目名称，不是必须使用的文件扩展名。

**使用支持 Skill 的 Agent：**把完整的 `skills/contributor/` 文件夹放进该 Agent 配置的技能目录，保留其中的相对路径。宿主支持 `$名称` 调用时可用 `$contributor`；其他宿主使用其自己的加载方式。`agents/openai.yaml` 是可选的界面元数据，不影响主流程。

**没有技能安装入口：**把项目交给能读取文件的 Agent，明确让它读取 `skills/contributor/SKILL.md` 并按其中流程工作。不需要复制完整聊天历史，也不需要先建立一份漂亮的能力档案。

第一次可以这样说：

> 使用 contributor。先根据当前对话和我指定的项目总结，归纳我长期用 AI 的领域、方法与判断，再去 GitHub 检索相关项目。结合当前技术、我的实践和你的分析，推荐一个有证据的贡献机会。现在只做发现，不对外发布。

选中机会后：

> 就做这个问题，复现并完成必要修复，按项目要求验证。先给我补丁和 PR 草稿。

准备提交时：

> 将刚才核对的补丁提交到该上游项目，使用我指定的 GitHub 账号和 fork。遇到同范围的常规操作继续完成，目标或改动范围变化再说明。

也可以一次授权一个已明确范围的“修复并提交 PR”任务，无需机械重复三个阶段。宿主和目标项目的权限要求仍然适用。

## 哪些积累能形成贡献

| 积累或变化 | 可能的贡献 | 必须验证的部分 |
| --- | --- | --- |
| 长期处理中文文件，知道跨平台输出的常见失败 | 编码/路径修复及回归用例 | 当前版本仍可复现，修复有效 |
| 已形成避免重复统计的分析 SOP | 数据检查、示例或现有流程中的一步 | 能解决项目实际场景，使用合成案例 |
| 新工具让原来的处理链路更简单 | 小范围适配或替代实验 | 同样输入下的收益、兼容与维护成本 |
| AI 更能梳理复杂逻辑 | 发现并修复此前遗漏的边界条件 | 代码与实验支持，而非模型判断本身 |

上表为说明性场景，不代表这些问题存在于任何当前仓库。贡献不局限于修 bug，也不以新技术为改动理由；机会成立后才动手。

## 工作边界

个人画像来自实际获准访问的材料。有项目总结就先看总结，不扫描整盘，不声称拥有宿主没有开放的会话记忆。私人材料先抽象成通用问题再检索；原始聊天、客户内容和内部信息不进入搜索词或 PR，演示使用重新构造的合成案例。

一次解决一个具体问题。没有合适机会可以不提交；不制造无关文档改动、不批量骚扰维护者、不扩大成平台重写。遵循许可证和项目对 AI 贡献的规则。用户只要寻找机会时，不创建 fork、推送分支或发消息。

## 依赖与兼容性

Skill 本身只有文本，无执行期软件依赖、订阅服务或单独 API 费用。

宿主需提供对应能力：归纳需要获准的材料；检索需要网络或 GitHub 读取工具；实现需要目标项目的开发环境；提交需要有权限的 GitHub 连接器或 Git/gh。网络、模型使用和 CI 成本取决于宿主与目标项目。缺少某项能力只阻塞相关阶段。

采用常见 `SKILL.md` 目录形式，当前不声称已完成所有 Agent 的兼容测试，也不自动安装或连接账号。

## 当前版本与验证

`0.1.0` 本地初版已完成：Skill 结构检查通过，单个独立 Agent 的一次离线验收中，8 个虚构场景均满足评分标准。尚未进行真实 GitHub 端到端或跨宿主验证，也不据此推算采纳率。方法见 [evals/README.md](evals/README.md)，完整记录与局限见 [evals/RESULTS.md](evals/RESULTS.md)。

项目目录：

```text
skills/contributor/   可独立安装的 skill 与私有记录格式
evals/                虚构场景、行为验收标准与验证记录
LICENSE               MIT 许可证
```

欢迎用具体失败案例改进 skill：它是否误读了个人经验、选错项目、扩大范围、夸大验证，或者遗漏维护者反馈。分享时使用合成材料，说明预期和实际结果；不上传私人会话或客户资料。

本地准备完成后，下一步是在用户选定的宿主运行一次真实“只发现机会”的任务，再决定发布版本。发布到 GitHub、安装到个人 Agent 或提交其他项目的 PR 都需要相应任务授权，不由本仓库自动执行。
